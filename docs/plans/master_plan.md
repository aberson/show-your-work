# show-your-work — master plan

Workflow transparency for every project: one centralized standard and CLI that scaffolds,
validates and renders a `docs/workflows/` folder inside each consumer project.

Planned 2026-10-24 via `/plan-init`. Pipeline position: plan-init → plan-review → plan-redline →
plan-wrap → repo-init → build-phase → repo-update.

## 1. What This Is

Proposal: docs/plan-redline/show-your-work-proposal.html (publication 3, 2026-10-28)

`show-your-work` is a standalone, local-first CLI (Python 3.12, stdlib runtime) that owns the
**per-project `docs/workflows/` standard**. A consumer project runs `show-your-work init` once to
scaffold the folder, authors workflow diagrams as mermaid `.mmd` files with a required header
block, runs `show-your-work check` to validate them against a legibility budget and the header
contract (anchored by a known-garbage fixture that must fail first), and runs
`show-your-work render` to regenerate the folder's `README.md` and a small `workflows.json` index
from the sources so nothing drifts. Optionally it renders light/dark PNG rasters through the pinned
`mermaidx` renderer. The documents live in the consumer project; this project is the template,
the validator and the generator. dev-observatory's planned workflows view (its master plan Steps
45-55) is the intended downstream reader of `workflows.json` and the rasters, and is **out of
scope** here.

**Origin.** The idea surfaced 2026-09-02 as a "workflows-viewer" seed
(`dev/docs/seeds/seed_workflows_viewer_observatory.md`) and grew a prototype at the coding root,
`dev/docs/workflows/`: seven `.mmd` diagrams, `check_diagrams.py` (validator) and
`render_readme.py` (README generator) with two independent header parsers, a draft artifact
contract, a renderer spike and an excalidraw-lane proposal. It never became a project. This plan
promotes that prototype into a reusable utility and makes the coding root its first consumer.

**Explicit non-goals (v1).** No Observatory routes, normalizer or static export (owned by
dev-observatory Steps 45-55). No run records, recipes or attempt ledgers (the Toolkit program's
"Workflows" product row is a different thing). No automated excalidraw conversion (browser-only by
design; the hand-edit lane remains a documented option, not code). No headless-Edge fallback
renderer. No daemon, server, database or network access.

## 3. Data Store

All data is flat files. Two locations: the **tool repo** (templates, fixtures) and each
**consumer project's `docs/workflows/`** (sources, generated outputs).

### 3.1 Consumer folder layout (the standard)

```
<project>/docs/workflows/
  intro.md                  hand-authored; project-specific prose the README embeds verbatim
  <id>.mmd                  one diagram per file; id = file stem (section 3.2)
  <id>.excalidraw.svg       OPTIONAL hand-edited lane for an id; sibling of its .mmd (section 3.5)
  <id>.layout.json          OPTIONAL hand-authored layout sidecar for an id; sibling of its .mmd
                            (section 2.4)
  README.md                 GENERATED by `show-your-work render`; never hand-edited
  workflows.json            GENERATED index, schema `show-your-work.workflows.v1` (section 3.4)
  rasters/                  OPTIONAL, GENERATED: `<id>-light.svg`, `<id>-dark.svg` by every `render`
                            for an id with a sidecar (section 2.5); `<id>-light.png`,
                            `<id>-dark.png` by `render --png`
```

Hand-authored files: `intro.md`, `*.mmd`, `*.excalidraw.svg`, `*.layout.json`. Generated files
carry a leading "GENERATED FILE - DO NOT EDIT" marker (README), a `"generator"` field (JSON) or
the fixed generator marker comment as the first child (house SVG, section 2.5). `render --check`
exits 1 when a generated file is out of date, so CI or a pre-commit hook can gate drift.

### 3.2 Diagram identity

- **id** = the `.mmd` file stem. MUST match `^[a-z0-9][a-z0-9-]{0,63}$` (the grammar
  `dev/docs/workflows/devobs-workflows-v1-contract.md` section 3 fixes, so the Observatory consumer
  never has to sanitize). A non-matching stem is **rejected, never sanitized**. Duplicate ids
  (impossible on a case-sensitive filesystem, possible on Windows via case variants) are rejected.
- Rename = new id. There is no alias table; the README anchor and `workflows.json` entry follow the
  stem.

### 3.3 Header contract (the one parser)

Every `.mmd` opens with a block of mermaid `%%` comment lines. The first non-empty header line is
the **title** (a colon in the title is fine). Then label lines of the form `Label: value`:

| Field | Required | Bound | Notes |
|---|---|---|---|
| title | yes | <= 120 chars | first `%%` line, verbatim |
| `Summary:` | yes | <= 160 chars | one sentence, shown in the contents list |
| `Sources:` | yes, >= 1 entry | each entry a repo-relative path or URL; **absolute machine paths rejected** (`^[A-Za-z]:[\\/]`) | value on the same line and/or `%%   - path` bullets below |
| `Not shown:` | yes | <= 400 chars | declared omissions; the legibility budget permits omission only when declared |
| `Alt:` | yes | <= 240 chars, ASCII, no control chars | describes the picture, never repeats the title; required because a raster with no text alternative is a defect (dev-observatory master plan Step 44) |
| any other label | — | **hard error** naming the label | an unrecognised field once fell silently into the sources list; fail loud |

Parsing rules, carried from both prototypes and unified: a bullet (`- ...`) is always a
continuation of `Sources:`, never a label; **every** label line clears the "in sources" state
(the `check_diagrams.py` version left it sticky, so an `Alt:` after `Sources:` was swallowed as a
source — a regression test pins this); the header ends at the first non-`%%`, non-blank line.
A **label line** matches `^([A-Za-z][A-Za-z ]{0,30}):(\s|$)` on the text after `%%` (the
prototype `render_readme.py` `LABEL_RE` plus a required space-or-end after the colon, so an
unbulleted `https://...` source is never mistaken for a label named `https`); label names compare
case-insensitively. A non-bullet, non-label `%%` line while in the "in sources" state is also a `Sources:` continuation
(both prototypes do this, and the real `measure-twice-benchmark-lifecycle.mmd` relies on it:
`%% Sources: measure-twice/README.md - Workflow section` followed by unbulleted
`%% measure-twice/CLAUDE.md - Architecture summary` lines). Outside that state a non-label line
after the title is a hard error `header-stray-line` (fail loud, never silently ignored). The title
is the first line verbatim even when it looks like a label (`%% Title: measure-twice benchmark
lifecycle` stays the title `Title: measure-twice benchmark lifecycle`; fixtures are carried
unchanged). Template-origin files carry a marker comment `%% show-your-work:template` as the
**last** line of the file (outside the header, so the parser never sees it) and
`<!-- show-your-work:template -->` as the last line of `intro.md`.
Whole file MUST be ASCII (bytes <= 127) and MUST NOT contain a machine-absolute `Users` path.
CRLF and LF are both accepted; every reader normalizes CRLF to LF before parsing, hashing or
embedding (the real `plan-to-build-pipeline.mmd` is CRLF today), so output never depends on a
checkout's `core.autocrlf`.

Legibility budget (checked by `check`), constants in one module, values from `check_diagrams.py`:
`MAX_NODES = 14`, `MAX_EDGES = 20`, `MAX_NODE_LABEL = 60`, `MAX_EDGE_LABEL = 40`,
`MAX_SUBGRAPHS = 2`, plus `subgraph`/`end` balance. Node/edge counts are exact only under
`--render` (read from the SVG mermaid produced); without the renderer they report `-` and the
run prints a NOTE, never a silent pass of those two checks.

Carried verbatim from `check_diagrams.py` (so the build does not depend on the prototype, which M1
deletes):

- `GARBAGE = "flowchart LR\n    A[unclosed --> ((( )))\n    ->> %%%% not a diagram\n    subgraph\n"`
  — the anchor; `mermaidx.render(GARBAGE)` MUST raise.
- SVG counts: nodes = matches of `class="[^"]*\bnode\b[^"]*"`; edges = matches of
  `class="[^"]*\b(?:edge-thickness|flowchart-link)\b[^"]*"`, falling back to `\bid="L[_-]` when
  that is 0.
- Source label lengths (body = non-`%%` lines): node labels `[\[\(\{]+\s*"([^"]*)"\s*[\]\)\}]+`
  plus `\[([^"\[\]\n]+)\]`; edge labels `\|\s*"?([^"|\n]+?)"?\s*\|`, `--\s+"([^"]+)"\s+-->`,
  `-\.\s+"([^"]+)"\s+\.->`. The longest of each is compared with the budget.

### 3.4 `workflows.json` index (schema `show-your-work.workflows.v1`)

```json
{
  "schema": "show-your-work.workflows.v1",
  "generator": "show-your-work 0.1.0",
  "generated_at": "2026-10-24T18:00:00+00:00",
  "source_dir": "docs/workflows",
  "items": [
    {
      "id": "release-checklist",
      "label": "Release Checklist",
      "summary": "The four gates a release passes in order ...",
      "alt": "Four boxes in a row joined by arrows ...",
      "not_shown": "hotfix path, rollback ...",
      "sources": ["docs/release.md"],
      "source_path": "docs/workflows/release-checklist.mmd",
      "source_sha256": "<64 hex>",
      "engine": "mermaid",
      "rasters": null
    }
  ]
}
```

- `items` sorted by `id` ascending; ids unique; exact key set per item (unknown keys are a
  generator bug, caught by a schema test).
- `label` = the header title verbatim; `summary` / `alt` / `not_shown` / `sources` = the parsed
  header fields (section 3.3), except that while a sidecar diagram's `rasters` are house entries
  its `alt` is the layout `alt`, falling back to the header Alt whenever `rasters` is `null` (D31:
  it describes the image the rasters show).
- `source_dir` = `TARGET` relative to its **project root** (the nearest ancestor containing a
  `.git` file or directory), POSIX separators; `source_path` = `<source_dir>/<id>.mmd`. When no
  `.git` ancestor exists (e.g. a tmp fixture copy), `source_dir` is `"."`. Output never depends
  on cwd.
- `source_sha256` is SHA-256 over the file's bytes after CRLF -> LF normalization (section 3.3).
- A plain `render` (no `--png`) **preserves** an existing item's `rasters` entry when both
  referenced files still exist and still match the entry's `sha256` and `bytes`, and writes
  `null` otherwise (Step 6 build decision, 2026-10-24: an index must never claim hashes the files
  on disk do not have); it never deletes PNG raster files (orphan house SVGs follow D25,
  section 4). The P12 provenance rule narrows the preservation: both files must be house PNGs
  (tagged with the `tEXt` marker, section 2.6 Step 10) exactly when the diagram has a sidecar, so
  adding or removing a sidecar writes `null` until `render --png` runs again. This
  is what lets `render --check` ignore raster hashes without `--png` (section 9).
- `engine` is `"mermaid"` unless `<id>.excalidraw.svg` exists beside the `.mmd`, then
  `"excalidraw"` (the `.mmd` becomes provenance; the SVG is truth — contract section 4).
- `rasters` is `null` until `render --png` runs; then
  `{"light": {"path": "rasters/<id>-light.png", "sha256": ..., "width": N, "height": N, "bytes": N}, "dark": {...}}`.
  A sidecar diagram's entries describe its house PNGs at the same paths with the same keys (P9).
- `generated_at` is ISO-8601 with a UTC offset of exactly zero (the Observatory normalizer rejects
  naive or non-UTC stamps).
- This is **not** the `devobs.workflows.v1` envelope. Observatory Steps 45-55 own a bounded
  mapping from this index to their envelope (they read `summary`/`alt`/`sha256`/dims from here).
  Nothing here mints Observatory `limits`, `summary` counts or asset paths.

**Determinism.** Given identical sources, `render` produces byte-identical `README.md` and
identical `workflows.json` except `generated_at`. `render --check` compares with `generated_at`
masked.

### 3.5 Excalidraw lane (documented, not automated)

Per `dev/docs/workflows/excalidraw-lane.md`: author in mermaid, convert once by hand at
excalidraw.com (Insert → Mermaid), save `<id>.excalidraw.svg` beside the `.mmd`, hand-edit in the
VS Code extension. The tool's only involvement: `check` requires that an `.excalidraw.svg` has a
matching `.mmd` (orphans fail), and `render` flips `engine`. Rasterizing the SVG is a non-goal.

### 3.6 Tool-repo layout for templates and fixtures

```

  example-workflow.mmd      minimal valid diagram carrying all five header fields
show-your-work/tests/fixtures/
  garbage/garbage.mmd       MUST fail every gate (the anchor)
  bad-headers/*.mmd         one missing field each, plus Alt-after-Sources, unknown label, abs path
  over-budget/*.mmd         15 nodes, 21 edges, 61-char label, 3 subgraphs, unbalanced end
  realistic/*.mmd           SYNTHETIC sample diagrams reproducing every edge case of the real
                            coding-root set (never copies of it; the repo is public, the real
                            diagrams are private workspace data — P6)
  realistic/intro.md        sample intro with a document table
  layout/                   Phase 2 sidecar cases (section 2.4): valid/, invalid/ (one
                            layout-invalid cause each), bound/ (one layout-bound rule each),
                            orphan/, png/ (the Step 10 house fixture), golden/ (house SVGs and
                            their README) and phase1/ (Phase 1 check and render goldens)
```

## 4. CLI contract

Console script `show-your-work`. Every verb takes an optional positional `TARGET` directory
(default: `./docs/workflows` resolved from cwd; if cwd has no `docs/workflows`, exit 2 with the
message `no docs/workflows at <abs path>; pass a target or run 'show-your-work init'`) — except
`init`, which creates the default target when it is missing (built behavior, 2026-10-24).
Discovery is **top-level only** (`TARGET/*.mmd`, non-recursive), so `rasters/` and nested fixture
folders are never scanned. Every usage error — unknown verb, unknown flag, missing value — exits
**64**: argparse's own default for usage errors is 2, which would collide with "gate could not
run", so `cli.py` overrides `ArgumentParser.error` to exit 64.

| Verb | Behavior | Exit codes |
|---|---|---|
| `init [TARGET] [--force]` | Create `TARGET` if missing; write `intro.md` and `example-workflow.mmd` from templates **only where absent** (never overwrite; `--force` overwrites template-origin files only); then run `check` and `render` on the result. | 0 scaffolded; 1 check failed on the scaffolded set (should be impossible — a test pins it); 2 target is a file / unwritable |
| `check [TARGET] [--render] [--json]` | Header contract, ASCII, abs-path, label budget, subgraph balance, excalidraw orphan check, id grammar, duplicate ids, layout sidecars (section 2.4). `--render` adds real mermaid render + exact node/edge counts via `mermaidx`; **before** any file, renders the embedded garbage fixture and aborts with exit 2 if it does NOT raise. | 0 all pass; 1 >= 1 file fails; 2 gate could not run (no `.mmd` files, `--render` without mermaidx, anchor broken, a source that is symlinked, unreadable or over the 256 KiB `MAX_SOURCE_BYTES` cap, a sidecar that is symlinked, unreadable or over the 64 KiB `MAX_LAYOUT_BYTES` cap) |
| `render [TARGET] [--check] [--png] [--json]` | Regenerate `README.md` + `workflows.json`, and `rasters/<id>-{light,dark}.svg` for every diagram with a sidecar (section 2.5). `--check`: write nothing, exit 1 if any of them is stale (a house SVG that is changed, missing or an orphan included). `--png`: also write `rasters/<id>-{light,dark}.png` (via mermaidx for a sidecar-less diagram, from the house SVGs for a sidecar diagram) and fill `rasters`. Runs `check` first (without `--render` unless `--png`); refuses to render a failing set. | 0 written / up to date; 1 stale (`--check`) or check failed; 2 cannot run (`--png` without mermaidx, anchor broken (mermaid or house), a raster canvas over the cap of 16384 px per side or 50 Mpx, `rasters/` not a plain directory when a file may be written there, an unmarked file at a house SVG path, a write failure) |

Human output is a fixed-width table (one row per file) plus a summary line
`N/M pass (budget: <=14 nodes, <=20 edges, node label <=60, edge label <=40, <=2 subgraphs)`.
`--json` emits `{"schema": "show-your-work.report.v1", "target": ..., "verb": ..., "files": [...], "summary": {...}, "exit_code": N}`
with deterministic key order:

| field | type | note |
|---|---|---|
| `target` | string | absolute TARGET, POSIX separators |
| `verb` | string | `check` / `render` / `init` |
| `files[]` | object | one per discovered `.mmd` (plus one per orphan `.excalidraw.svg` and one per orphan `<id>.layout.json`; every other `layout-*` finding attaches to its `.mmd` row, section 2.4), sorted by file name: `{"file": "<name>", "id": "<stem>", "pass": bool, "nodes": int \| null, "edges": int \| null, "findings": [{"code": str, "message": str}]}` (`null` counts = not rendered) |
| `summary` | object | `{"total": int, "passed": int, "failed": int, "rendered": bool, "budget": {"nodes": 14, "edges": 20, "node_label": 60, "edge_label": 40, "subgraphs": 2}}` |
| `exit_code` | int | the process exit code |

Finding codes are stable strings defined once in `constants.py`: `header-missing-title`,
`header-missing-summary`, `header-missing-sources`, `header-missing-not-shown`,
`header-missing-alt`, `header-bound` (a field over its length bound), `header-unknown-label`,
`header-stray-line`, `alt-repeats-title`, `alt-not-ascii`, `abs-path`, `non-ascii`, `id-grammar`,
`id-duplicate`, `excalidraw-orphan`, `budget-nodes`, `budget-edges`, `budget-node-label`,
`budget-edge-label`, `budget-subgraphs`, `subgraph-unbalanced`, `render-error`, and the layout
sidecar codes (section 2.4) `layout-invalid`, `layout-bound`, `layout-stale`, `layout-orphan`.

**Generated README shape** (`render`): GENERATED marker → `# Workflow diagrams` →
`intro.md` verbatim → `## Contents` (one bullet per diagram: `[title](#anchor) - summary`) → per
diagram: `## title`, summary, `Source:` link, `Drawn from:` source bullets, `**Alt:**`,
`**Deliberately not shown:**`, the mermaid fence → `## Regenerating` footer with the exact
command. A diagram with a sidecar replaces its mermaid fence with the section 2.5 `<picture>`
embed (the fence moves inside `<details>`) and labels its Alt line `**Alt (mermaid source):**`;
when the folder has at least one sidecar, the GENERATED marker and the footer carry the section
2.5 sentences. Anchor slug = GitHub rule (lowercase, drop punctuation including colons, spaces
→ `-`); a test pins the colon case `"Release Checklist: One Gated Ship"` →
`release-checklist-one-gated-ship` (synthetic title; test strings never quote the private
coding-root diagrams, P6).

**PNG rendering** (`--png`), for a diagram without a sidecar: inject a mermaid front-matter config
block carrying `theme` (`default` / `dark`) and `flowchart: { wrappingWidth: 400 }` (without it
mermaidx breaks long tokens mid-word — 3 of 6 seed diagrams, spike section "Fidelity"); call
`png(scale=2, background=...)` with `scale = 2` and an **opaque** per-theme background (`#ffffff`
light; `#333333` dark, mermaid's dark-theme `background` variable — Step 6 confirms it against the
mermaidx bundle and records the confirmed value) — constants in one module, asserted by tests;
never transparent. Sources stay config-free. A diagram with a sidecar is instead rasterized from
its section 2.5 house SVGs through `resvg_py` with the bundled DejaVu Sans Mono fonts and system
fonts skipped (P8), at the same `scale = 2` on the opaque card fill (D29), and tagged as a house
PNG with the `tEXt` marker (section 2.6 Step 10). The mermaid anchors run only when the folder has
a sidecar-less diagram and the house anchors (D22) only when it has a sidecar diagram. Orphan PNG
cleanup (`--png` only) deletes only regular `*.png` files directly inside `rasters/` that the new
index does not reference — never recursing, never following symlinks, never touching another file
type. Orphan house SVGs are the one other deletion, on every `render`, under D25: only a regular,
marked `*-light.svg` / `*-dark.svg` directly inside `rasters/`, deleted last.

## 5. Modules

### `src/show_your_work/`

- `__init__.py` — version string, public exports.
- `constants.py` — the ONE home for data-shape constants: budget numbers, header field names and
  bounds, id regex, schema strings, raster scale/background, `GARBAGE` fixture text.
- `header.py` — `parse_header(text) -> Header | HeaderError`: the single parser (section 3.3).
  Dataclass `Header(title, summary, sources, not_shown, alt)`.
- `checks.py` — `check_dir(target, *, renderer) -> Report`: file discovery, id grammar,
  duplicate/orphan detection, header, ASCII, abs-path, label budget, subgraph balance, optional
  render counts. `Finding(file, code, message)`; codes like `header-missing-alt`,
  `id-grammar`, `budget-nodes`.
- `layout.py` — the layout sidecar (Phase 2): `parse_layout(raw) -> Layout | LayoutError`,
  `layout_findings` (the section 2.4 `layout-bound` rules and the `layout-stale` hash pin) and
  `draw_svg(layout, theme) -> str` (the section 2.5 house SVG engine).
- `renderer.py` — thin optional wrapper over `mermaidx`: `load() -> Renderer | None`,
  `anchor_ok(renderer) -> bool` (garbage must raise), `svg(src)`, `png(src, theme) -> bytes`,
  front-matter injection, counts-from-SVG regexes (from `check_diagrams.py:counts_from_svg`),
  and the house raster path (Phase 2): `house_png(svg, theme) -> bytes` and the house anchors.
- `render.py` — README builder, `workflows.json` builder, `--check` comparison with
  `generated_at` masked, house SVG + raster writing + orphan cleanup.
- `scaffold.py` — `init`: copy templates where absent, `--force` semantics.
- `cli.py` — argparse, verb dispatch, exit-code mapping, `--json` emitter. `main(argv) -> int`.

## 8. Key Design Decisions

**DD1 — One parser, five required fields, Alt from day one.** The prototype had two independent
header parsers that already disagreed (sticky `in_sources` in one, loud unknown-label error in the
other). dev-observatory Step 44 planned to teach *both* about `Alt:`. This project makes that step
moot: one `header.py`, `Alt:` required, every label clears the sources state, unknown labels fail
loud. Code-quality rule "one source of truth for data-shape constants" applies: bounds and names
live in `constants.py` and tests assert identity, not equality.

**DD2 — Documents live in the consumer; the tool owns templates, checks and generators.**
Operator direction 2026-10-24. The consumer project can read its own `docs/workflows/README.md`
on GitHub with native mermaid rendering before any tool or viewer exists; the tool is what keeps
the folder honest. The tool never maintains a central list of other projects' diagrams.

**DD3 — Migrate, don't copy, and the coding root is the first consumer.** Operator decision
2026-10-24. Two copies of the seven diagrams would drift (exactly what the generated README was
built to prevent). The real diagrams **never enter this repo**: it is public machinery, and the
real diagrams are private workspace data (P6, operator 2026-10-24). The tool is tested on real
content by a read-only test that runs against the live `dev/docs/workflows/` in a tmp copy when
present (Step 5), plus synthetic `realistic/` fixtures that reproduce its edge cases. The live set
is migrated by the operator (M1), where the Alt lines and `intro.md` are authored in the private
coding-root repo, because the coding root is a different git repository than this project and a
build-step worktree cannot edit it.

**DD4 — `workflows.json` is this tool's index, not the Observatory envelope.** The draft
`devobs.workflows.v1` contract carries Observatory-specific `limits`, `summary` counts and
project-relative asset paths that only the Observatory producer can state truthfully. This index
carries what a consumer needs to build that envelope (ids, text fields, source hash, raster hash
and dims) and nothing it would have to guess. Observatory Steps 45-46 should be amended to read
this index instead of re-parsing `.mmd` headers (follow-up, section 9).

**DD5 — Renderer optional, pinned, anchored.** `mermaidx==0.9.5` lives in an optional extra so
`uv sync` for the stdlib verbs pulls no wheels. Every render path first renders a known-garbage
fixture and aborts with exit 2 if it does not raise — the spike's harness bug (both fixtures
reported FAIL) is exactly what this anchor catches. Frozen raster parameters (`scale=2`, opaque
backgrounds, `wrappingWidth: 400`) are constants because an unpinned scale silently changes every
hash and dimension a downstream artifact declares.

**DD6 — `init` never overwrites.** A consumer's hand-authored `intro.md` and diagrams are the
truth; `init` is idempotent and only fills gaps. `--force` re-copies template-origin files only
(detected by a template marker comment), never a user diagram.

**DD7 — Excalidraw is a documented lane, not code.** The conversion is browser-only by design and
the embedded-scene claim is unverified (`excalidraw-lane.md`). v1 recognises the sibling file and
records `engine`; that is all.

### 2.4 Layout sidecar contract (`<id>.layout.json`)

UTF-8 JSON object, at most `MAX_LAYOUT_BYTES = 65536` bytes, read through `read_source` (which gains a
`limit` parameter, default `MAX_SOURCE_BYTES`, and a layout-specific too-large message); an oversize
or symlinked sidecar is a gate error (exit 2, like a symlinked `.mmd`). Parsed with an
`object_pairs_hook` that rejects duplicate keys and a `parse_constant` that rejects NaN / Infinity;
any `ValueError` (including an integer over the int-string digit limit) or `RecursionError`,
non-UTF-8 bytes, unknown keys, missing keys and wrong types (booleans are never integers) are all
`layout-invalid`. Every string is printable ASCII (0x20-0x7E); a string outside that range (for
example a decoded `\u00e9` or `\n` escape) is `layout-bound`. All indexes are 0-based integers.

| field | type | rule (violation -> code) |
|---|---|---|
| `schema` | string | exactly `show-your-work.layout.v1` (`layout-invalid`) |
| `source_sha256` | string | 64 lowercase hex, else `layout-invalid`; a well-formed value that differs from the CRLF->LF SHA-256 of the sibling `<id>.mmd` is `layout-stale` (message names the expected hash) |
| `alt` | string | 1..`MAX_ALT` (240) chars; describes THIS drawing (`layout-bound`) |
| `lanes` | array | 2..6 lanes (`layout-bound`) |
| `lanes[].label` | string | 1..16 chars, uppercase letters, digits, space, `+`, `-`, `/` (`layout-bound`) |
| `lanes[].in`, `lanes[].out` | int | index of a NON-side node in that lane (`layout-bound`) |
| `lanes[].nodes` | array | 1..4 nodes (`layout-bound`) |
| `nodes[].name` | string | 1..22 chars (`layout-bound`) |
| `nodes[].sub` | string | 0..27 chars (`layout-bound`) |
| `nodes[].side` | bool | node 0 is never side; a side node must be the lane's LAST node (`layout-bound`) |
| `nodes[].branch_label` | string | 1..14 chars when `side`, `""` otherwise (`layout-bound`) |
| `loops` | array | at most one per lane; `{lane, from, to}` with `from == to + 1`, both in range, neither side (`layout-bound`) |
| `rejoin` | object or null | `{from_lane, from_node, to_lane, to_node, label}`: `from_lane != to_lane` (either direction, D30: a feedback loop such as playtest -> build); `from_node` / `to_node` are the LAST node of their lanes (side allowed); `label` 1..40 chars (`layout-bound`) |

Also: a sidecar without a sibling `<id>.mmd` -> `layout-orphan`; a sidecar next to an
`<id>.excalidraw.svg` -> `layout-bound` (the excalidraw drawing is already the truth for that id).
Report rows: `layout-orphan` gets its own `files[]` row for `<id>.layout.json` (like
`excalidraw-orphan`); `layout-invalid` / `layout-bound` / `layout-stale` findings attach to the
`<id>.mmd` row (its `pass` turns false), so `summary.total` still counts `.mmd` files plus orphan rows.

### 2.5 Engine (authoritative for Step 9; px, numbers printed with `format(v, "g")`)

Pill `W=200`, gutter `G=40`, margin `M=20`, first row `TOP=50`, row pitch `ROWH=60`, pill height
`NH=46`, side drop `SIDE_DROP=22`. Lane `i` x = `M + i*(W+G)`; node `k` y = `TOP + k*ROWH`
(`+SIDE_DROP` if side). Canvas width `SVG_W = 2M + n*W + (n-1)*G` (`W` is always the 200 px pill
width; `SVG_W` / `SVG_H` are the canvas). `nodes_bottom` = max over lanes of last-node y + `NH`.
With a rejoin: baseline = `nodes_bottom + 24`, `SVG_H` = baseline + 22; else `SVG_H` =
`nodes_bottom + 26`.

Root: `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 SVG_W SVG_H" width="SVG_W" height="SVG_H"
font-family="ui-monospace,'Cascadia Code','SF Mono',Consolas,'DejaVu Sans Mono',monospace"
role="img" aria-label="ALT">`, first child the fixed marker comment `<!-- generated by
show-your-work render; do not edit -->` (no id inside: ids may contain `--`, which XML forbids in
comments). Fixed element order: marker comment; `<defs>` (exactly as the reference SVGs:
`<marker id="ar" markerWidth="9" markerHeight="9" refX="7.5" refY="4.5" orient="auto">` with path

markerHeight="10" refX="7.5" refY="5" orient="auto">` with path `M0,0 L10,5 L0,10 Z` filled with the
spine token; no viewBox and the default `markerUnits` (strokeWidth), so arrowheads scale with the

stdDeviation=4`); card rect `x=6 y=6 rx=16` (`SVG_W-12` x `SVG_H-12`, card-fill fill, card-stroke stroke 1.5); lane labels left to right
at (lane x, 34): 11 px, weight 600, letter-spacing .12em; spine paths left to right (stroke 2.4,

### 2.7 Risks

| Item | Consequence | Mitigation | Blocking |
|---|---|---|---|
| `resvg-py` API drift | `svg_to_bytes` kwargs change | exact pin `resvg-py==0.5.0`; one call site (`renderer.house_png`) | no |
| README references generated SVGs | broken images if `rasters/*.svg` is not committed | D20 writes them on every render; README tells consumers to commit them; Step 11 dogfoods it | no |
| CRLF checkouts | byte-exact SVG comparison fails on Windows | `.gitattributes` LF rules (Steps 8, 9, 11); consumer guidance in README | no |
| Browser vs PNG font | browsers draw the SVG with the viewer's mono font | both monospace; limits sized for 0.602 em (2.5) | no |
| Font licence / integrity | redistribution needs the licence; drifted bytes change hashes | `LICENSE-DejaVu.txt` shipped; pinned SHA-256s asserted (Step 10) | no |
| Sidecar authoring cost | consumers write JSON by hand | out of scope; agents can draft (as in the walkthrough) | no |

### 2.8 Testing strategy

Narrow: `tests/test_layout.py` (every 2.4 rule and code, hash pin incl. CRLF), `tests/test_layout_svg.py`
(goldens plus formula-derived geometry), `tests/test_png.py` additions (pixel + provenance). Every
Done-when runs through `cli.main`. End-to-end: Step 11 real `--png` on a tmp copy, then M3 in a real
consumer. Commands (from `CLAUDE.md`): `uv sync --extra dev --extra render`, `uv run pytest -q`,
`uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy --strict src tests`. Obligations:
compatibility - `workflows.json` v1 unchanged and sidecar-less folders byte-identical except the P12 provenance null (Steps 8-10);
producer/consumer seam - Step 11 real-CLI run, then M3; not autonomous or scheduled (one-shot CLI);
no deployment seam.
